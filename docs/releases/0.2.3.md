# Forenotes 0.2.3

Release preparation. Merge the reviewed release branch into `main`, then tag the
validated merge commit as `v0.2.3` to publish both container images.

## Changes

- Fix MCP observation and hypothesis writes on PostgreSQL by reusing the outer
  transaction's connected client instead of attempting to reconnect it.
- Accept `indicator` and `ioc` when linking MCP entities. Relationships store the
  canonical `ioc` type, and unsupported entity or relationship types are rejected
  during input validation.
- Preserve required provenance: observations need evidence support, and
  hypotheses need observation support.
- Add JSON HTTP access logs to stdout for completed requests, including method,
  path, status, duration, and outcome.

No new database migrations are required compared with 0.2.2.

## Upgrade after publication

Wait for both image publishing jobs to succeed. Back up PostgreSQL, `/app/data`,
and `.env.production`, and preserve `FORENOTES_LLM_SECRET_KEY`.

Update these image pins in the existing `.env.production`:

```dotenv
FORENOTES_IMAGE=ngynduc/forenotes:0.2.3
FORENOTES_REPORT_LLM_IMAGE=ngynduc/forenotes-report-llm:0.2.3
```

```bash
docker compose --env-file .env.production -f docker-compose.prod.yml pull
docker compose --env-file .env.production -f docker-compose.prod.yml up -d
docker compose --env-file .env.production -f docker-compose.prod.yml ps
```

Both services should become healthy. Retry observation creation before creating
a hypothesis with the returned observation ID. Reconnect MCP clients to refresh
the tool schemas if necessary.

Installer defaults remain pinned to the published 0.2.2 images during release
preparation. Promote those defaults separately after both 0.2.3 images are available.
