# Forenotes 0.2.5

Tag the validated `release/v0.2.5` commit as `v0.2.5`, wait for tag CI to
succeed, then merge the branch into `main`. The `main` workflow publishes both
container images from the validated tag without repeating the test suite.

## Changes

- Accept report requests up to 50 MiB and report Markdown up to 10,485,760
  characters. Oversized JSON now returns `413` instead of a generic `500`, and
  authentication plus incident membership are checked before parsing the larger
  body.
- Store newly saved report Markdown and generated context in the private app
  data volume under `/app/data/reports`. PostgreSQL retains report metadata and
  a file reference.
- Keep existing PostgreSQL-backed reports readable. Editing their Markdown
  moves the body to app storage without requiring a bulk migration.
- Clean up report files when database writes roll back and remove replaced or
  deleted files only after their database transaction commits.
- Keep full report bodies out of report deletion audit records.
- Validate version tags once, then publish the validated tag after it is merged
  into `main` without rerunning lint, tests, or the application build.

Migration `011_report_file_storage.sql` adds the nullable `content_file`
reference. Existing report rows remain unchanged. There are no dependency
updates compared with 0.2.4. See the
[regression validation record](./0.2.5-validation.md).

## Upgrade after publication

Keep a matched backup of PostgreSQL, `/app/data`, and `.env.production` before
upgrading. Preserve `FORENOTES_LLM_SECRET_KEY`.

Set these image pins in the existing `.env.production`:

```dotenv
FORENOTES_IMAGE=ngynduc/forenotes:0.2.5
FORENOTES_REPORT_LLM_IMAGE=ngynduc/forenotes-report-llm:0.2.5
```

```bash
docker compose --env-file .env.production -f docker-compose.prod.yml pull app report-llm-service
docker compose --env-file .env.production -f docker-compose.prod.yml up -d app report-llm-service
docker compose --env-file .env.production -f docker-compose.prod.yml ps
```

The app applies migration `011` before startup. Open an existing report, then
save, reopen, and export a large report. New and Markdown-edited reports require
the app data volume as well as PostgreSQL.

After the upgraded app saves file-backed reports, rollback requires restoring
the matching pre-upgrade database dump and app-data archive. Changing only the
image tag can leave older code unable to read those report bodies.

Installer and Compose defaults stay on published images during preparation.
Promote those defaults only after both 0.2.5 images are available.
