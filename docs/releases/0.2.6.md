# Forenotes 0.2.6

Tag the validated `release/v0.2.6` commit as `v0.2.6`, wait for tag CI to
succeed, then merge the branch into `main`. The `main` workflow publishes the
application image from the validated tag without repeating the test suite.

This release ships a single image. The separate `forenotes-report-llm` image is
no longer built or published.

## AI reports

- **AI Report Chat** drafts reports in a streaming conversation. The model reads
  incident data through two read-only tools (`get_incident_overview`,
  `query_incident_data`) under the caller's permissions, and the answer can be
  saved straight into the new **Report Editor**.
- **Chat Prompt** stores per-user report instructions on top of fixed built-in
  rules (`GET`/`PUT /api/me/report-chat-prompt`).
- The app calls OpenAI-compatible Chat Completions APIs directly. The Python
  LiteLLM service, its image, and `LITELLM_SERVICE_URL` are removed. Known
  providers (OpenAI, Anthropic, Gemini, OpenRouter, xAI, Groq, Z.ai, Ollama)
  need no endpoint; other provider names require `LLM_API_ENDPOINT`.
- PDF export (and Chromium) is removed; reports export as themed HTML. The
  Markdown template, template guide, and template-preview tabs are removed from
  the UI. Their API endpoints remain.
- **Test connection** shows the provider's error message with the API key
  redacted.

## Investigation workspace

- The relationship graph starts with findings only; clicking a finding reveals
  its direct neighbours in a non-overlapping layout.
- Timeline events have a `primary` or `supporting` role; supporting events
  expand from their primary event in the graph.
- Findings and timeline events show creator, owner, timestamps, evidence,
  related entities, and tags.
- `DELETE /api/users/:id` deactivates the account instead of deleting it,
  revoking sessions and MCP tokens while preserving attribution.
- The Markdown editor follows the light or dark theme.

## Stability

- The database pool has a 10 s connection wait, `DB_POOL_MAX` (default 20),
  `DB_STATEMENT_TIMEOUT_MS` (default 60000), and a 5-minute idle-transaction
  limit. Dropped idle connections are logged instead of crashing the process.
  Migrations use a separate pool without these limits.
- Provider requests time out after `LLM_TIMEOUT_MS` (default 180000). LLM
  routes run outside the per-request transaction.
- `/api/health` queries PostgreSQL and returns `503` when it is unreachable.
- `SIGTERM` closes the server and pool within 10 s; unhandled rejections are
  logged and uncaught exceptions exit for the restart policy.
- Production Compose waits for PostgreSQL before starting the app.
- The investigation runs incident filter no longer fails on the in-memory demo
  database.
- The app image is about 290 MB instead of 1.4 GB; unused `better-sqlite3` is
  removed.

Migrations `012_timeline_event_roles.sql` and `013_report_chat_prompts.sql`
add timeline roles and per-user chat prompts. See the
[regression validation record](./0.2.6-validation.md).

## Upgrade after publication

Keep a matched backup of PostgreSQL, `/app/data`, and `.env.production` before
upgrading. Preserve `FORENOTES_LLM_SECRET_KEY`.

Download the 0.2.6 `docker-compose.prod.yml`, then set the image pin in the
existing `.env.production` and delete `FORENOTES_REPORT_LLM_IMAGE` and
`LITELLM_SERVICE_URL`:

```dotenv
FORENOTES_IMAGE=ngynduc/forenotes:0.2.6
```

```bash
docker compose --env-file .env.production -f docker-compose.prod.yml pull app
docker compose --env-file .env.production -f docker-compose.prod.yml up -d --remove-orphans app
docker compose --env-file .env.production -f docker-compose.prod.yml ps
```

`--remove-orphans` stops the old `report-llm-service` container. Then run
**Settings → LLM → Test connection** and ask AI Report Chat a short question.
Chat needs a model that supports tool calling.

API clients that call `POST /api/incidents/:id/reports/:reportId/export/pdf`
must switch to `/export/html`.

Rollback across migrations `012` and `013` requires the matching pre-upgrade
database dump and app-data archive.

Installer and Compose defaults stay on the published 0.2.5 image during
preparation. Promote them to 0.2.6 only after the image is available.
