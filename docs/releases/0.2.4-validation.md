## Real PostgreSQL commander concurrency

Use a disposable local database whose name ends with `_regression_lab`.
The test rejects other database names and remote hosts, applies migrations,
creates synthetic records, and cleans up its own records afterward.

```bash
docker run -d --rm --name forenotes-patch-regression-pg \
  -e POSTGRES_USER=postgres \
  -e POSTGRES_PASSWORD=local-regression-only \
  -e POSTGRES_DB=forenotes_regression_lab \
  -p 127.0.0.1:55439:5432 postgres:16-alpine
docker exec forenotes-patch-regression-pg pg_isready -U postgres

# Run once PostgreSQL reports that it accepts connections.
FORENOTES_TEST_DATABASE_URL=postgres://postgres:local-regression-only@127.0.0.1:55439/forenotes_regression_lab \
  npx vitest run src/server/tests/membershipConcurrency.test.ts

docker stop forenotes-patch-regression-pg
```

Expected: both concurrency tests pass. Deleting a commander while removing or
demoting another returns one `204` and one `409`, preserving one commander.

## Additional validated behavior

- Production cookie authentication: new sessions expire after four hours;
  reads do not extend expiry; expired cookies and header authentication fail.
- Case commanders can load the minimal case member directory while
  `/api/users` remains restricted. Add, role change, remove, and re-add work.
- Account deletion revokes sessions and MCP tokens, writes an audit record,
  and emits the session-ended event only after commit. Referenced accounts
  return `409` with their sessions, settings, memberships, and tokens intact.
- Concurrent account deletions retain the last case commander.
- Browser role updates disable member controls and clear the candidate list.
- Assignment visibility preserves graph positions and other relationships;
  MITRE/custom tags remain available on records and in the separate matrix.

The review fixed candidate-cache clearing after role changes and serialized
commander removal/demotion with account deletion. Database migrations,
dependencies, MCP implementation, and Docker configuration are unchanged.

Existing sessions keep their stored expiry after an upgrade. Sign out and
back in to receive the new four-hour session. This validation record does
not indicate that a release has been tagged or published.
