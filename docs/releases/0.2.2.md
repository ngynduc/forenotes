# Forenotes 0.2.2

Release preparation. Images and the Git tag have not been published yet.

## Changes

- Production installs include the Python report LLM service. The app waits for its healthcheck and reaches it through the internal Compose network. The release workflow publishes matching app and report-service images.
- Installer reruns configure missing or empty report-service URLs while preserving credentials, existing app image pins, and external report-service URLs.
- Optional authenticated MCP investigation tools support case-scoped runs, evidence, observations, hypotheses, draft findings, provenance, and audited agent writes. MCP tokens inherit their owner's current access. MCP remains disabled by default; see [MCP setup](../MCP.md).
- Name-based API discovery covers users and agents.
- User editing updates existing accounts through PATCH, with validation, permission checks, and audit records.
- ATT&CK tags can be attached and removed from findings, timeline events, and queries. Tag edits refresh the MITRE matrix and relationship graph.
- Relationship graphs use measured node dimensions, preserve dragged positions during refreshes, and provide Auto layout.
- Password changes revoke browser sessions. Profile, role, membership, and scope changes refresh through the existing single-process realtime stream, with access reconciliation after reconnect.

## Upgrade

Back up PostgreSQL, `/app/data`, and `.env.production` before upgrading. Preserve `FORENOTES_LLM_SECRET_KEY`; replacing it prevents decryption of stored provider keys.

After both images are published, download the release Compose file into the existing installation directory:

```bash
curl -fsSLo docker-compose.prod.yml \
  https://raw.githubusercontent.com/ngynduc/forenotes/v0.2.2/docker-compose.prod.yml
```

Update these values in the existing `.env.production`:

```dotenv
FORENOTES_IMAGE=ngynduc/forenotes:0.2.2
FORENOTES_REPORT_LLM_IMAGE=ngynduc/forenotes-report-llm:0.2.2
LITELLM_SERVICE_URL=http://report-llm-service:8001
```

Keep a configured external `LITELLM_SERVICE_URL` if using an independently hosted report service. Provider credentials still need configuring in user settings or `LLM_*` variables; the service starts without them.

```bash
docker compose --env-file .env.production -f docker-compose.prod.yml pull
docker compose --env-file .env.production -f docker-compose.prod.yml up -d
docker compose --env-file .env.production -f docker-compose.prod.yml ps
docker compose --env-file .env.production -f docker-compose.prod.yml \
  exec app sh -c 'wget -qO- "$LITELLM_SERVICE_URL/health"'
```

Startup applies migration `010_mcp_provenance.sql`, including investigation records, MCP tokens, and finding provenance. Test upgrades on a restored local backup first. Rolling back across this schema change requires the matching pre-upgrade database and data backup.

Incident access remains case-wide. Removing a member through the compatibility incident-membership endpoint now removes parent-case membership and access to its incidents. Password changes require a new login.
