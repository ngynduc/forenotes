---
title: From case to report
description: Follow the primary Forenotes investigation workflow from initial scope to final communication.
---

Use this guide when starting a new investigation. The goal is a report whose conclusions remain traceable to the underlying evidence and response work.

## 1. Create the case

Create a case for the engagement or investigation. Use a clear name, identify the client or organization, set the working dates, and summarize the scope.

![Create case form](/user-guide/create-case.png)

Add only the people who need access. Assign at least one case commander so membership can continue to be managed safely.

![Cases list](/user-guide/cases.png)

## 2. Add an incident

Create an incident for the security event being investigated. Set severity and status based on the current assessment; both can change as evidence develops.

![Create incident form](/user-guide/create-incident.png)

Use separate incidents when events require independent timelines, task boards, evidence sets, or reports.

## 3. Build the factual record

Add timeline events for observations and preserve their source or raw-evidence reference. Record affected systems, accounts, and indicators as soon as they become stable investigation facts.

Avoid writing conclusions into every timeline item. Timelines answer **what happened and when**; findings answer **what it means**.

## 4. Record and support findings

Create findings for analyst conclusions. Include the impact, confidence, and recommended response—not just a title.

![Findings table](/user-guide/findings.png)

Link each finding to the records that support it. A reviewer should be able to open the finding and follow the evidence trail without reconstructing your reasoning from chat or external notes.

![Add finding form](/user-guide/add-finding.png)

## 5. Coordinate remaining work

Create tasks for collection, validation, containment, stakeholder follow-up, and report review. Set an owner or assignee, priority, status, and due date when applicable.

Use task notes for working detail. Keep durable evidence and conclusions in their dedicated records.

## 6. Review relationships

Open the entity graph to find disconnected records, unclear manual relationships, and findings with weak evidence support. Use MITRE ATT&CK tags to communicate observed techniques, not as a substitute for evidence.

## 7. Produce the report

Open Reports, choose or create a template, build the report context, and generate a draft. Review every generated statement against the source records before saving or exporting it.

The investigation is ready for handoff when another authorized responder can understand the event, inspect the evidence behind each material finding, see open work, and reproduce the report narrative from Forenotes.
